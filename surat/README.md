# Surat Real Estate Data Cleaning

## Overview

This project focuses on cleaning and structuring a real estate dataset containing property listings from Surat.

The original dataset contains several real-world data quality problems such as mixed units, inconsistent categorical values, information stored in the wrong columns, currency symbols, missing values, and columns containing multiple pieces of information in a single field.

The main goal of this project was to transform the raw dataset into a more structured and analysis-ready dataset using Python and Pandas.

---

## Dataset

The raw dataset contains **4,525 property records**.

The original dataset includes information such as:

- Property area
- Square feet
- Transaction type
- Property status
- Floor information
- Furnishing
- Facing direction
- Property description
- Price per square foot
- Property price

The raw data was stored in:

`surat_uncleaned.csv`

The cleaned dataset generated by the notebook is:

`surat_cleaned.csv`

---

## Problems Found in the Raw Data

The dataset was not ready for analysis because several columns contained inconsistent or incorrectly placed values.

Some of the issues included:

- Different area units such as `sqft`, `sqyrd`, and `sqm`
- Non-area values appearing inside the area column
- Currency symbols and text inside price columns
- Prices represented using `Lac` and `Cr`
- Incorrect values appearing in the transaction column
- Transaction information appearing in the floor column
- Furnishing information appearing in other columns
- Mixed values in the status column
- Floor information stored as values such as `5 out of 10`
- Missing values in several columns
- Unwanted information inside categorical columns
- Property type and location combined inside `property_name`

---

## Data Cleaning Process

### 1. Standardizing Column Names

Column names were converted to lowercase to maintain consistency.

For example:

`areaWithType`

was converted to:

`areawithtype`

---

### 2. Extracting Apartment Type

The original `property_name` column contained information such as:

`2 BHK Apartment for Sale in Dindoli Surat`

Two useful pieces of information were extracted from it:

- Apartment type
- Location

The apartment type was cleaned using pattern matching so that values such as:

`2 BHK`

`3 BHK`

`4 BHK`

could be stored separately.

---

### 3. Cleaning Area Information

The `square_feet` column contained values with different units.

Examples included:

- `644 sqft`
- `33 sqyrd`
- `89 sqm`

The data was standardized into square feet.

Conversions used:

- `1 sqyrd = 9 sqft`
- `1 sqm ≈ 10.7639 sqft`

Values that did not represent valid area measurements were treated as missing.

---

### 4. Cleaning Transaction Information

The transaction column contained several values that did not actually represent transaction types.

Valid transaction values were retained, while unrelated values were removed.

In some rows, furnishing information had accidentally appeared in the transaction column. Those values were moved to the furnishing column before being removed from transaction.

---

### 5. Cleaning Property Status

The original status column contained detailed descriptions such as:

- `Ready to Move`
- `Poss. by Dec '24`
- `Poss. by Dec '25`
- `Resale`

These were converted into simpler categories:

- `Ready`
- `Under Construction`
- `Resale`

This makes the column easier to analyze.

---

### 6. Cleaning Floor Information

The raw floor column contained values such as:

`5 out of 10`

This was separated into two columns:

- `current_floor`
- `total_floors`

For example:

`5 out of 10`

became:

```text
current_floor = 5
total_floors = 10
